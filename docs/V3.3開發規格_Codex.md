## 一、滑鼠拖曳畫面（小需求，先做，約半天）

現況：除小地圖外，只能用 WASD／方向鍵或貼邊捲動移動畫面。

**滑鼠拖曳畫面（SEVEN 追加需求）**：目前除了小地圖，只能用 WASD／方向鍵或貼邊捲動移動畫面。→ 在地圖上**按住滑鼠左鍵拖曳即可移動畫面**（抓地圖的手感：游標往右拖，畫面往左移，世界跟著游標走）。
- 實作位置：`src/15_main.js` 的 `onCanvasDown`（目前 mousedown 只做選人/施法）。改為：mousedown 記錄起點與起始 `Render.cam`；`mousemove`（綁在 `window`，游標拖出畫面也不中斷）超過 **4px（舞台座標）**才視為拖曳，`Render.cam.x/y = 起始cam − (目前游標 − 起點)/2`（畫面縮放為 ×2），並呼叫 `Render.clampCam()`；`mouseup`／視窗失焦／`modals` 開啟時結束拖曳。
- **點擊與拖曳要分開**：位移 < 4px 的 mouseup 才算「點擊」，才執行原本的選人／施放神力／神眼；拖曳結束**不得**誤選人或誤施放神力。
- 拖曳時：`Game.follow = 0`（取消自動跟隨）、游標變抓手（`cursor: grabbing`，平時地圖上可 `grab`）、關閉貼邊捲動避免衝突；小地圖的視窗框同步更新。
- 手感：拖曳 1:1 無慣性（可選：放開後 150ms 輕微慣性）；邊界以 `clampCam` 夾住。
- 右鍵維持「取消神力」；觸控板雙指拖曳也應可用（`wheel` 事件：`deltaX/deltaY` 平移）。
- 相容：教學期間拖曳仍可用，且**不得**讓教學的「點擊光亮居民」步驟被拖曳誤觸發。
- 驗收（Playwright）：①按住左鍵從 (800,400) 拖到 (500,300)，`Render.cam` 變化量 = (+150,+50)（÷2 後）且 `Game.selId` 不變；②4px 以內點擊居民仍可選人；③有選中神力時拖曳不施放；④拖到邊界不超出 `clampCam`；⑤拖曳中游標移出畫面再放開，狀態正確結束。

## 二、視覺與 UI 升級


### 2.0 現況診斷（為什麼看起來像 GB）

對照 `src/11_sprites.js`：
1. **整張圖都是 `fillRect` 純色塊**：地形每格 1 底色＋2～3 個小點；樹是幾個長方形疊起來；沒有漸層、沒有色階。
2. **角色只有 16×24、每個部位 1 種顏色、無輪廓線**：皮膚/衣服/褲子各一色，沒有「暗面・底色・亮面」三階，也沒有深色外框，所以在草地上「糊在一起」。
3. **建築是色塊＋招牌**：屋頂沒有瓦片紋、牆沒有磚/木紋、沒有陰影與窗光。
4. **沒有統一光源**：陰影只是半透明黑橢圓；沒有地面接觸陰影、沒有牆面受光差。
5. **UI 框線是單色粗線**：沒有 FF 系那種「漸層底＋雙層邊框＋圓角像素」質感；游標、圖示簡陋。
6. **沒有環境動態**：水面、草、樹、煙、旗幟、火光不動或動很少。

> 要達到 FF5：不是「換顏色」，是**改變作畫方法**——從「用矩形拼」改成「像素逐點設計（palette-indexed pixel maps）＋色階＋外框＋抖色（dither）＋動畫幀」。

---

### 2.1 核心作法：Sprite DSL（用字串逐點畫圖）

**把「用 fillRect 拼」改成「用字元矩陣逐點畫」**，這是在無外部圖檔下做出 FF5 細膩度的唯一實際方法。

```js
// 例：16x24 劍士，下方向，站立幀（示意；實際由 Codex 逐點設計）
const SPR_SWORDSMAN_DOWN_0 = [
 "......oooo......",
 ".....ohhhho.....",
 "....ohhHHhho....",
 ...
];
// 字元 → 色階索引：o=外框 h=髮底 H=髮亮 s=膚底 S=膚亮 d=膚暗 c=衣底 C=衣亮 k=衣暗 ...
// 繪製時依角色的 hair/skin/cloth 查「色階表」換色（recolor），不必每種組合畫一次
```
- 新增 `src/11a_spritedata.js`（圖資字串）與 `11b_palette.js`（色階表＋recolor＋快取）。繪製入口維持 `humanSprite(h, dir, frame)` 等現有函式名，**呼叫端不改**。
- 每個色系 **4 階色階（暗／底／亮／高光）＋ 1 階外框色**，且做**色相偏移**（暗面偏冷、亮面偏暖），不要只是單純變暗/變亮。
- 全部圖資在啟動時渲染到 offscreen canvas **快取**（現有 `spriteCache`、`worldCache` 沿用）；執行期 0 次逐點運算。

### 2.2 規格明細

#### 角色（最優先，玩家 90% 時間在看人）
| 項目 | 現況 | 目標 |
| --- | --- | --- |
| 尺寸 | 16×24 | **維持 16×24**（相容座標），但內部用滿像素，頭身比約 3 頭身（FF5 field sprite） |
| 方向×幀 | 4 方向×3 幀 | 4 方向×**4 幀走路**（站/左/站/右），另有「待機呼吸」2 幀 |
| 著色 | 單色塊 | 膚/髮/衣/褲/靴**各 3 階＋外框**；髮型 ≥ 8 種輪廓（短/長/馬尾/捲/禿/兜帽…），明顯不同 |
| 職業辨識 | 衣服變色 | 每職業**專屬輪廓**：劍士（劍＋護肩）、魔法師（尖帽＋長袍＋法杖）、僧侶（頭巾/法衣）、藥師（圍裙＋藥瓶）、農夫（草帽＋農具）、商人（背包）、鐵匠（圍裙＋鎚）、盜賊（兜帽）、史官（書＋羽筆）、騎士等；**嚴禁**職業與持物不符（對應 B0-F2） |
| 年齡 | 縮放 0.78 | 孩童**單獨畫**（頭大身小），老人（駝背＋白髮/鬍） |
| 狀態 | 少 | 受傷（蹲/紅閃）、祈禱（雙手合十＋小光點）、戰鬥（出劍/施法）、死亡（倒地→靈魂光點）各 ≥ 1 幀組 |
| 外框 | 無 | **選擇性外框（selective outline）**：外輪廓深色、內部色塊交界用較淡暗色，不是整體黑框 |

#### 地形與地圖
- **Autotile（邊緣過渡）**：草↔路、草↔水、草↔沙、路↔廣場有邊角過渡（至少 13-tile 簡化版），**不再出現直角硬切**。
- **每種地面 ≥ 3 個變體**（隨機散布，避免棋盤感）：草（含花/小石/草叢）、路（車轍/碎石）、石板（縫與磨損）。
- **水**：4 幀流動（波紋亮線移動）＋岸邊白色泡沫線＋倒影（樹/房子在水中的暗色鏡像，簡化即可）。
- **季節**：春（花瓣）、夏（深綠）、秋（落葉、橙色調）、冬（積雪覆蓋＋冰面）——**不只換底色**，要有專屬貼圖（雪堆在屋頂與樹上）。
- **樹**：三層樹冠（暗/中/亮）＋樹幹樹皮紋＋地面陰影；有 3 種樹形（圓、尖、枯）。
- **小物件（新增 ≥ 20 種散布）**：木桶、箱子、水井、晾衣繩、花盆、路燈、告示牌、乾草堆、籬笆（有轉角）、墓碑、石燈、旗幟。

#### 建築
- 每棟 **屋頂瓦片紋（橫排）＋牆體紋（木板/石磚）＋門（有把手/門框）＋窗（有窗櫺）**；受光面/背光面兩階明暗；屋簷下投影 2px。
- 職業建築有**可辨識招牌與外型**（教會＝十字架尖塔＋彩窗、酒館＝啤酒杯招牌、鐵匠＝煙囪冒煙＋砧、旅館、商店、藥局、公會＝旗）。
- **煙囪煙**（3–4 幀緩升）、**窗光**（夜晚亮橙色，白天暗）、**風車/旗幟**動畫。
- 面積與座標不改（不影響碰撞、尋路）。

#### 光影與氛圍
- **統一光源（左上）**：所有物件陰影方向一致（接地陰影為偏藍的暗色橢圓，非純黑半透明）。
- **晝夜**：目前若為單層暗色疊加，改為**多段色調**（清晨偏粉、正午清晰、黃昏橘紅、夜晚藍紫），夜晚窗光/火把/路燈**局部提亮**。
- **天氣粒子**（雨、雪、落葉、花瓣）：輕量、可關。
- 魔王覺醒後：天空/地面加**紫黑色調與黑霧邊緣**，視覺上呼應天秤傾斜。
- 神力演出：恩寵（金光柱＋上升光點）、神諭（光紋擴散）、試煉（雷光）、干涉靈魂（藍色漣漪）——各 ≥ 12 幀的粒子演出，1 秒內結束，不遮擋操作。

#### 怪物與魔王
- 每種怪物 ≥ 2 幀待機＋1 幀攻擊，外框與 3 階著色；魔王與幹部為**大型 sprite（≥ 32×40）**，有獨立剪影，覺醒後有光環。

#### UI（保持 SEVEN 認可的黑底白字）
- **視窗框**：9-slice 像素框：**外白邊＋內層細線＋角落 2px 圓角像素＋底部漸層（黑→深藍黑，FF5 感）**；標題列用淡色底條。不改配色邏輯與可讀性（正文對比 ≥ 7:1）。
- **游標**：FF 式**指示手指（▶ 手形）**像素游標，選取時輕微左右搖動。
- **圖示（16×16）**：神力（神諭/恩寵/試煉/干涉靈魂/勢力操作）、天秤、信仰、職業、需求（飢餓/安全/財富/歸屬/名譽/信仰）、事件類型——全部像素逐點設計。
- **人物肖像（48×48）**：人物卡與史官書庫章首用大頭像（髮型/膚色/職業配件，3 階著色），比現在的 16×24 縮圖大。
- **天秤**：金屬質感（亮/暗/高光），盤上光與暗隨傾斜動畫擺動。
- **標題／選神畫面**：多層視差（星空/雲/神殿剪影），選神卡使用神的專屬圖像（程式生成的象徵圖形＋光暈），不是純文字卡。
- **字型**：保持系統字型（無外部素材），但**標題用大字＋2px 描邊/陰影**；數字（HP/信仰力）用自製 5×7 點陣字（程式內嵌）以保持點陣一致感。
- 動態：視窗開啟 6 幀展開、按鈕按下位移 1px、新祈禱卡閃光 1 次。

#### 畫面比例與渲染
- 以**整數倍放大**（最近鄰）顯示，避免模糊；現行 `stage` 以 1280×720 縮放，請確認縮放為整數倍或啟用 `image-rendering: pixelated`，非整數倍時以黑邊補。
- 相機移動以像素對齊（`Math.round`），避免走路時畫面抖糊。

### 2.4 效能與工程

- 圖資字串＋離屏快取；啟動時渲染，**啟動時間 ≤ 1.5 秒**（一般 PC）；執行期維持 60fps（現況 36 人＋怪物）。
- `index.html` 增量 ≤ 約 600KB（圖資字串可壓縮：用 RLE 或 base36 打包再於啟動時展開）。
- 新增 `test/sprite_sheet.js`：自動輸出**總覽圖**（角色/地形/建築/UI/圖示）到 `test/out/`，供人工驗收；同 seed 截圖可重現。
- 圖資與繪製分離：`11a_spritedata.js` 只放資料；日後換美術（或人工精修）只改資料檔即可。
- 規則 1（無外部素材）不變；若日後採用外部繪製的圖，需改為「可選素材包」，無包時退回程式生成。

### 2.5 驗收流程（只驗收一次）

**交付前（Codex 自己完成，全部過才算交付）**
1. 自動檢查全綠：smoke／lang／soak／batch3／story_check／readability；效能（啟動 ≤ 1.5 秒、36 人＋怪物 60fps）；碰撞/尋路/點選範圍無退步；日/中文字不被新框線截斷。
2. 產出**驗收包**到 `test/out/visual/`（一次產齊）：
   - 角色總覽圖（全職業×4 方向×走路幀；孩童/老人/各狀態）
   - 地形總覽圖（含 autotile 邊角、水動畫幀、四季各一張 64×40 全景）
   - 建築總覽圖（白天＋夜景）
   - UI 總覽圖（視窗框、游標、圖示、肖像、天秤、標題/選神；日/中各一份）
   - 主畫面前後對比（v0.2 vs 新版；春正午／夏黃昏／秋清晨／冬夜 各 1 張）
   - 神力演出 GIF 或連拍（恩寵/神諭/試煉/干涉靈魂/勢力操作）
   - 一天 24 小時延時（每 3 小時 1 張）
3. 自我評分表（對照下列「品質門檻」逐條打勾，附證據圖）。

**品質門檻（自動＋目視）**
- 角色在草地/路/水/石板上都**輪廓清楚**（外框＋3 階著色），遮掉名字仍可辨識至少 6 種職業；
- 地形無直角硬切、無明顯棋盤重複；水有動畫；四季一眼可分；
- UI 正文對比 ≥ 7:1；名字標籤、祈禱光點、眷顧金環在任何地形上一眼可見；
- 無外部檔案、無網路請求；`index.html` 增量 ≤ 約 600KB。

**驗收（SEVEN 只做這一次）**：打開新版 `index.html` 玩幾分鐘＋看驗收包。**交給 SEVEN 之前，先由 Claude 對照驗收包與實機截圖做一次預審**（找出辨識不清、色階不協調、遮擋、錯位），不合格退回 Codex 修，合格才交 SEVEN。SEVEN 最終評分：「點陣細膩度接近 FF5」≥ 4/5。
