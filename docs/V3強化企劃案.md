## A. 對 V2 提案的評價（給你和 Codex 的判斷依據）

**整體判斷**：V2 抓對了病根——「系統在運作，意義沒有被傳達」。方向正確，約八成可直接採用。需要修正的是：①規模偏大，部分屬於「正式版 LLM 產線」，不該塞進單檔原型；②有幾處與現行已定設計或原型機制衝突；③漏了幾個我在試玩中實際撞到的問題（人名、用詞、配色、平衡、信仰經濟）。

### A3. 不建議（原型階段不做）

1. **改時間速度為 1/5/50 倍**：現行 ×1/×4/×16/×64 已完成並通過測試，不必動。
2. **LLM 級場景寫作、Continuity Editor、Style Editor、雙語分離生成管線**：正式版範圍；原型用模板，但模板必須吃 Scene Card 資料。
3. **教學期間把天秤、顧問、名簿鎖到「20 分鐘後」**：見 A2，過長。
4. **在原型階段新增職業、國家、神格、神力**：與 V2 自己的「核心未成立前不堆內容」一致，維持不新增。

6. **把「史官世界內敘事」完全取代為「全知小說」**：會失去本作與其他 AI 小說工具的差異（有偏見、不全知的史官）。保留兩層，不互相取代。

## 0. 共通規則（不可違反）

1. 單一 `index.html`（由 `src/*.js` 以 `node build.js` 產生）；無網路、無外部素材；程式生成圖與音。
2. 日文／繁體中文**同步**；兩語各自撰寫，不互為直譯；新增文字兩語一起交付。
3. 模擬使用 seeded RNG；新增的選文、選章、教學偏置都走同一個 seed（同 seed → 同結果）。
4. 事實由模擬鎖定：章節/場景只能引用已存在的事件、人物、關係、持有物；**不得生成模擬中不存在的事實**。
5. 不做小遊戲；成否判定維持 4 級（大成功/成功/曲解/失敗）。
6. 不新增職業、國家、神格、神力種類。
7. 文字量限制：任何卡片主文 ≤ 2 句（日 ≤ 60 字、中 ≤ 40 字），其餘放「展開」。
8. 既有存檔格式 `rinne_tenbin_v1_slot1` 若不相容，需版本號遷移或明確提示。
9. 每個里程碑完成後跑 smoke／lang／soak／batch3 與新增測試，附日/中截圖各 6 張。

## 1. V3 定位與三根支柱

**一句話**：玩家不是替角色寫人生，而是在有限神力下，選擇見證與推動哪些人生，讓它們活成一本小說。

三根支柱（所有需求必須歸屬其一）：

1. **看得懂**：第一分鐘知道自己是誰、能做什麼、現在該做什麼、這一局要什麼。
2. **會在乎**：認得出人、記得住少數人、知道他想要什麼。
3. **像作者**：看得見自己的選擇如何回響，史官寫的是「誰的故事」而不是事件清單。

**體驗目標（驗收句）**
- 1 分鐘：能說出「我是神，透過祈禱與神力間接影響居民，不能直接命令」。
- 3 分鐘：完成第一次觀察＋第一次介入。
- 10 分鐘：記住至少 1 名角色並說得出為何在意。
- 15 分鐘：理解天秤是「世界活力與毀滅風險」而非善惡條。
- 30 分鐘：看到至少一次「過去介入→現在結果」的因果回響。
- 一季結束：能說出這一季主要是誰的故事、主題是什麼、自己的哪個選擇改變了結局。

## 2. 新手引導（P0）

### 2.1 神的三個動詞與四句話（開場，史官口吻，大白話）
- 你是這個世界的神，不是國王。
- 你不能直接命令人，只能用神諭、恩寵、試煉輕輕推動他們。
- 你不用救所有人，也不用讓人類永遠贏。
- 你要做三件事：**聽見**（祈禱）→ **選擇**（介入／等待／沉默）→ **承擔**（後果之後才來）。

### 2.2 腳本化教學 9 步（可跳過、可從選單重玩、教學中時間暫停）
| 步 | 內容 | 解鎖 |
| --- | --- | --- |
| 0 | 神醒來：三動詞；只剩世界與一個大按鈕「聽見祈禱」 | 暫停狀態 |
| 1 | 第一個祈禱（保證出現，固定為「重病的家長」類型）；光柱引導；其他居民暫不可選 | 人物選取 |
| 2 | 人物卡簡版：是誰／想要什麼／現在狀況／為何重要；進階屬性可展開 | 人物卡 |
| 3 | 選擇：恩寵／神諭／**保持沉默**；各顯示 立即作用／故事可能／風險／見效時間 | 神力列（2 種）、信仰力 |
| 4 | 結果（故事語言）＋「因果種子」；說明 4 級結果意義 | 結果橫幅、種子面板 |
| 5 | 學時間：解鎖速度鍵；顧問：「神的選擇不會立刻開花」 | 速度鍵、暫停 |
| 6 | 第一次因果回響（見 2.3）；自動暫停 | 回響面板 |
| 7 | 第一次閱讀史官：打開書庫看第零章（主角標示、POV 說明） | 史官書庫 |
| 8 | 第一名眷顧者；說明跨世追蹤 | 眷顧者面板 |
| 9 | 最後解鎖天秤與全 HUD；顧問說明天秤＝活力與毀滅風險 | 天秤、顧問、名簿、靈魂之河 |

### 2.3 教學回響必須是「真的」
- 使用**教學種子世界**（固定 seed，小規模 12–18 人）。
- 教學專用事件採「機率偏置」而不是硬寫：被神救下者之子女，在教學世界中被救後的「職業選擇」權重上調（例如藥師），並在 N 年窗內觸發「救人」事件的權重上調。
- 若模擬沒有按預期發生：顧問用**誠實保底文案**（「結果還沒有開花——這就是神的工作。我們先看另一條線。」），並由第二備援種子補一次回響，不得偽造事件。
- 教學結束後，進入正式新局（不同 seed），不沿用教學世界。

### 2.4 UI 解鎖原則
- 只在教學流程內分段解鎖，教學結束（或跳過）後**全部開放**。
- 設定項：「完整 UI で開始／完整 UI 開始」；老玩家可跳過教學。
- 教學中被鎖定的 UI 以半透明遮罩顯示，附一句用途（滑過時）。

## 3. 主畫面資訊層級（P0）

### 3.1 三層
1. **現在要注意什麼**（最醒目）：本局執念、當前神務、緊急祈禱、將高潮的故事、重大危險。
2. **可以做什麼**：神力列（名稱／成本／目標類型／用途／疲勞狀態）、觀察、追蹤、暫停與速度。
3. **查資料才用**：居民名簿、靈魂表、因果細項、事件紀錄、統計。

### 3.2 HUD 配置（沿用既有版面，增補）
- 上方中央：`本局執念` ＋ `當前神務`（可收合）；進度（執念線索 x/y、中期天命）。
- 右上天秤：文字＋趨勢＋原因（例：`光 18 穩定／趨勢：向暗傾斜／原因：近期魔物襲擊、2 次未回應的祈禱`）。
- 右側：分「緊急祈禱」與「故事升溫」兩區。
- 下方：神力列；左下：時間控制＋自動暫停設定（祈禱／眷顧者危機／故事高潮）。
- 常駐「？」按鈕（不藏進 Esc 選單）：我現在該做什麼？／這個 UI 是什麼？／神力怎麼用？／天秤是什麼？／故事線怎麼形成？／重玩教學。
- 通知移至側邊通知欄，不遮地圖中央（§8）。

### 3.3 三層目標常駐
- 短期「神務」（每數分鐘）；中期「時代天命」（例：十年內培養 3 名可抗魔王軍的冒險者）；長期「神之執念」（開局選擇，原型提供 3 個預設）。
- 原型預設執念：①讓一對跨世靈魂相守 ②培養英雄但不讓他成為下一任魔王 ③讓魔王與勇者放下仇恨。
- 執念進度必須可計算（例：線索 0/2＝已發現「具前世羈絆的靈魂」數）。

### 3.4 顧問「我現在該做什麼？」
- 每次最多 3 條：緊急處理／故事機會／長期風險；每條必有「為什麼」「可做什麼」「不保證結果」。
- 不給唯一解；資料來源是祈禱佇列、故事線狀態、天秤趨勢。

## 4. 人物辨識與連結（P0）

### 4.1 地圖名字標示（V2 未涵蓋，試玩最大痛點）
- 居民頭上顯示名字（白字黑邊小字）。分層：
  - 常時顯示：眷顧者（★金牌）、祈禱者（頭上光點/「！」）、聚光燈主角、選取／滑過者、勇者／魔王候補。
  - 其他居民：職業小圖示；縮放到一定倍率或按住 `N` 才顯示全員名字。
- 設定「名字顯示：全部／重要者／無」，預設「重要者」；教學與前 3 日暫用「全部」。
- 標籤自動避讓不重疊；40 人同畫面可讀。
- 職業顏色／圖示、眷顧金環、祈禱「！」。
- 祈禱卡 ↔ 地圖互相連動（滑過高亮、點擊移鏡）。

### 4.2 人物卡第一頁回答 5 問
這是誰／他想要什麼／他最怕失去什麼／他和誰有關／為何現在值得在意；屬性放第 2、3 頁。需求與動機沿用現有「なぜ」動機軌跡。

### 4.3 命運舞台
- 世界仍有 36 人，但同時只把 3–8 人放到舞台中央：主角候選、活躍故事線人物、眷顧者、將高潮者、與玩家過往神力有關者。
- 每條線顯示：標題／焦點人物／階段／未解問題／與玩家的關聯。

### 4.4 眷顧者 V2（原型版）
保存：歷代姓名與職業、每世渴望與遺憾、關鍵羈絆、玩家介入次數、未完成執念、代表物與名台詞。轉生辨識分三層：既視感 → 神眼確認 → 故事揭曉（原型至少做前兩層）。

## 5. 祈禱與神力（P0）

### 5.1 祈禱卡
先寫人與情境，再列選項。範例結構：
```
〔人名〕的祈禱：「……」（一句原話）
職業・年齡｜與你的過往（曾回應過／第一次）｜為何重要（若他死，哪條線會斷）
選項：恩寵｜神諭｜干涉靈魂｜保持沉默｜標記觀察（遇危機自動暫停）
每個選項顯示：建議度（◎○△）＋成功率＋成本
```
### 5.2 神力卡四層
機械效果／敘事意圖／風險／見效時間（立即・數日・數年・下一世）。例：`神諭｜成功率 76%｜成本 6｜立即：提高前往北方的傾向｜故事：可能推進師徒分離｜風險：被理解為「師父不需要我」｜見效：數日～數年`。

### 5.3 結果與沉默
- 結果橫幅用故事語言＋一行原因與後果；數值放展開。
- 「保持沉默」顯示：`你選擇不回應。這不是失敗，而是把命運交還給居民。`；記錄為事件，日後可成為回響來源。

## 6. 因果種子與因果回響（P0，本作核心賣點）

### 6.1 資料
```js
// 玩家介入產生種子
seed = { id, t, castId, targetId, kind /*grace|oracle|trial|soul|faction|silence*/,
         result /*great|ok|twisted|fail*/, tags:[], state:'dormant'|'sprouting'|'bloomed',
         linkedThreadIds:[], bloomEventIds:[] }
// 重大事件記錄成因
event.causes = [ { eventId, strength:0..1 } ]; event.playerCauseIds = [seedId...]
```
### 6.2 規則
- 重大事件（英雄成名、死亡、轉生揭曉、章節高潮）追溯最多 3 層因果，找出 `playerCauseIds`；有結果才顯示「因果回響」。
- 回響卡：`✦ 因果正在回響｜現在：…｜←(n 年前)…｜←(m 年前)你回應了…`；自動暫停（S 級）。
- 種子狀態在 UI 可追蹤，但**不顯示唯一答案**（不劇透）。
- 回響不得偽造：只用模擬中真實存在的因果邊。

## 7. 故事線引擎（P0 骨架 / P1 完整）

### 7.1 管線
```
模擬 → 事件日誌 → Story Thread → Character Arc → Chapter Card → Scene Card(模板) → 章節文字
```
史官每次問的是：「這件事改變了哪條故事？」

### 7.2 Story Thread（原型資料）
```js
thread = { id, title, theme, status /*candidate|active|developing|dormant|climax|resolved|legacy*/,
  priority, protagonistId, focusIds:[], supportIds:[],
  desire, fear, falseBelief, secret, centralQuestion, arcStage /*setup|desire|conflict|change|crisis|payoff*/,
  promises:[], foreshadowIds:[], playerSeedIds:[], eventIds:[], lastAdvancedTick }
```
- 啟動分數（權重）：關係重大變化 20／明確渴望與阻礙 15／可能失去重要事物 15／與玩家神力直接相關 15／前世執念宿命 15／可連既有伏筆 10／新鮮度 10。
- **聚光燈名額（原型）**：同時活躍 3 條（主 1＋次 2）＋ 候補 3；超出的事件只進人物誌與「雜記」短報。立傳名額＝此名額（取代舊的「立傳 3 人」說法，兩者合一）。
- 玩家可「請史官追這個人」，提高權重，但不保證精彩。

### 7.3 章節：品質閘門與標示
章節生成前檢查：POV 明確？有目標？有阻礙？章首章末狀態是否改變？是否推進至少一條線？是否新增／回收伏筆？是否有下一話鉤子？
- **「狀態改變」與「推進故事線」至少成立一項，否則不成章**，改入「雜記」。
- 標題：`【第n章】〈POV〉の／的…`；頁首：`POV｜所屬線｜地點｜日期｜第k話`；章首「前情」1–2 句；章末鉤子 1 句。
- 左欄可切「依時間／依人物／依故事線」；人物名下顯示 第1話、第2話…；有「追蹤此人」。
- 同一 POV 連續 2–4 話後才換；5 章內不得出現相同標題。

### 7.4 章量與品質目標
- 一局章數由約 125 章降到 **60–80 章**；其餘為「雜記」（短報，不計章）。
- 章型 ≥ 40 種 × 每型 ≥ 6 組變體；同句每局 ≤ 2 次；近 N 章用過句進黑名單；氛圍句依季節＋天氣＋POV 心情＋場景組合。

### 7.5 伏筆（有狀態的物件）
```js
foreshadow = { id, type /*relic|oath|catchphrase|scar|letter|prophecy|lie|false_belief|past_life_habit|oracle|myth*/,
  title, originEventId, ownerId, linkedThreads:[], meaning, timesShown,
  state /*born|seen|reappeared|dormant|paid|legacy*/, possiblePayoffs:[], notBefore }
```
- 不強制全部回收；回收必須改變人物／關係／讀者理解（章內標 ☆）。
- 同一伏筆最多提醒 3 次；跨世回收有專屬演出；玩家「伏筆之筆」提高保存與回收權重但不保證。
- 年末列「未解の謎／未解之謎」。

### 7.6 人物接力與遺產
死亡不終結故事：弟子、子女、仇敵、轉生者、遺物、未竟誓言、被誤解的傳說可作為接力媒介；線進入 `legacy`。UI 顯示 `✦ 命運線重新連接`。

### 7.7 Scene Card（模板填空）
```js
scene = { id, threadId, povId, arcStage, place, time, goal, opposition,
  povKnows:[], povDoesNotKnow:[], whatOtherWants, requiredChange,
  plant:[], payoff:[], forbiddenFacts:[], endHook }
```
文字模板只能在 Scene Card 範圍內取材；`forbiddenFacts` 命中即退回重選模板。

### 7.8 規則式 Continuity Checker（原型版）
每章產出後檢查：人物是否活著、年齡、所在地、是否「知道」此事、關係狀態、遺物持有者、誓言是否真的說過、前世是否已揭曉、人稱／稱號一致；不通過則換模板重試，三次仍失敗則降為「雜記」。

## 8. 通知、暫停與信仰經濟

- 通知分級：**S 必停**（結局、魔王覺醒、眷顧者死亡、重大因果回響、主線高潮）／**A 醒目**（緊急祈禱、伏筆回收、關係翻轉、故事線啟動）／**B 側邊紀錄**（升級、普通委託、小戰鬥、一般生老）。
- 通知顯示於側邊通知欄（可點擊跳轉、可回看歷史），**不遮地圖中央**；S 級停留較久。
- 自動暫停（設定可關；新手預設開）：祈禱、眷顧者危機、故事高潮、重大回響、魔王覺醒。
- **祈禱空窗保證**：祈禱空窗超過 N（可調）遊戲日時，提高祈禱生成權重（非固定計時器）。
- **信仰經濟**：避免信仰力長期卡上限 150——超出的溢出轉為「神殿／儀式資源」，可用於神眼或提升上限；並讓不同緊急度祈禱的信仰收益有差（救急 > 平常）。具體數值由 Codex 先給兩版方案並用 30 seeds 驗證。

---

## 9. 史官與小說：兩層成品

### 9.1 史稿模式（遊戲中）
世界內史官；有偏見、有資訊限制；標示目擊／轉述／推想；可暫時誤解；章節遵守 §7.3。

### 9.2 小說模式（結局後）
- 由「Book Director（規則版）」依完整事實重組：決定選一個**序章鉤子**（高潮瞬間或最強意象）→ 回溯；挑 5–7 章（短篇切片）精編；其餘折入附錄。
- 規則：Chronology ≠ Storytelling，但**不改事實、不改角色知識、不改因果**；史官誤記可作為劇情元素，不得造成基本矛盾。
- 結局時加入「**全史梗概**」一頁（3–5 條線＋玩家的關鍵介入）。
- 小說模式的 LLM 版（Scene Writer／Style Editor）留正式版。

---

## 10. 文字語言難度（P0，V2 未涵蓋）

- 文風：輕小說口吻、短句（中 ≤ 25 字、日 ≤ 40 字）、一句一事、對話多。
- 建立 `style_glossary`（禁用／替換詞表）：文言與生僻詞改日常詞（例：彌留→快不行了、戕害→傷害、遂→於是、乃→是）；日文避免文語調（〜なり／〜べし）與難讀漢字。
- 專有名詞首次出現附白話（因果＝善行與惡行的累積；曲解＝神意被誤解了…）。
- 「史官曰」要針對該章 POV 的選擇與因果，禁止通用格言。
- UI 用語同步白話化（眷顧→守護或加註；勢力操作等加提示）。
- 自動檢查 `readability_check`：禁用詞 0、平均句長達標、四字成語比例上限。

## 11. 原型垂直切片「短編モード / 短篇模式」（P0→P1）

先證明一本短篇能成立，再放大：
- 一座小鎮、**12–18** 名可辨識居民、1 核心主角＋2 共同主角、**3 條**故事線；
- 1 次重大祈禱、1 次玩家造成的延遲因果、1 次死亡、1 次轉生或前世揭曉、1 個遺物伏筆、1 次魔王決戰；
- 30–45 分鐘（×4 速）完成；產出 **5–7 章**、能從頭讀到尾的短篇。
- 教學種子世界即此模式的縮小版；正式新局仍可用 36 人完整模式，兩者並存（標題選單可選）。

## 12. 驗證（全部要能在本機自動跑，不連網）

| 檢查 | 工具 | 通過標準 |
| --- | --- | --- |
| 故事品質 | `test/story_check.js`（30 seeds × 兩語系） | 標題互異 ≥ 60%、句子獨特率 ≥ 85%、同句 >2 次 = 0、連續 5 章同題 = 0、第 2 話起含承接引用 ≥ 80%、種下後 3 年內伏筆回收 ≥ 50%、章頁首含 POV = 100%、Continuity 錯誤 = 0 |
| 可讀性 | `test/readability_check.js` | 禁用詞 0；平均句長中 ≤ 20 字 |
| 教學 E2E | Playwright | 9 步可完走、可跳過、可重玩；教學期間世界時間不前進；第一祈禱必出現 |
| 因果回響 | 腳本 | 教學世界 N 個備援 seed 中 ≥ 95% 在窗內產生真實回響；其餘走誠實保底 |
| 名字標示 | Playwright 截圖 | 40 人時標籤不重疊；眷顧者／祈禱者必顯示；兩語不截斷 |
| 平衡 | 30 seeds × 2 policies | 無介入：勝 35–55%／滅世 30–50%；基本介入：勝 ≥ 75%／滅世 ≤ 15% |
| 可重現 | 同 seed 兩次跑 | 章節、事件序列完全一致 |
| 試玩紀錄 | 本機 `localStorage` 匯出 JSON（選單：匯出試玩紀錄） | 記錄：第一介入耗時、教學完成/跳過、各 UI 首次開啟時間、暫停次數、回響首次出現時間；**不連網、無個資** |

**新手體驗目標（真人測試用的初值，需實測調整）**：90% 五分鐘後能說出神的三項核心行為；85% 三分鐘內完成第一次介入；80% 不看外部說明找得到祈禱／神力／暫停；75% 十分鐘後能說出天秤基本意義；70% 十五分鐘後能說出兩名重要角色及關係；80% 理解不介入也是合法選擇；「不知道現在要做什麼」回報率 < 15%。

## 13. UI 配色與可讀性

- **預設改黑底白字（DQ 式）**：背景 `#000`～`#0a0a14`、白色粗邊框＋內側細線、直角像素風；功能色：金（信仰／眷顧）、淡藍（光／善）、淡紅（闇／惡）、黃綠（成功）、橙（警告）。

- 對比：正文 ≥ 7:1、小字 ≥ 4.5:1；不只靠紅綠區分；小字級整體放大一檔（祈禱卡、資訊卡）。

## 17. 應保留（不要因修改誤刪）

神不能直接操控居民；居民有自由意志可誤解／拒絕；神力有成本與副作用；結果延遲；天秤不是越光越好；眷顧者跨世追蹤；前世因果影響下一世；英雄與魔王同源；史官有目擊／轉述／推想；事實由模擬鎖定；日/中獨立撰寫；單機買斷、成品屬玩家；不做小遊戲。

## 18. 不應走偏

不變成直接操控勇者的 RPG；顧問不給唯一解；不把所有居民塞進小說；不讓普通事件亂跳通知；不為連貫而讓程式自由創造新事實；不一次解釋所有系統；核心未成立前不堆內容；小說輸出不是結局後的附贈品。
