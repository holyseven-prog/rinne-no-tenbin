## B0. 劇情邏輯硬傷（M0 最優先，2026-10-02 追加；比 B 節其他項更重要）

**症狀（用戶試玩截圖，第 1 世第 1 年）**
1. 魔法師「海倫」在第 2 章結尾「主動開始揮劍練習」。
2. 第 2 章主角是海倫，第 3 章突然變成〈丹恩與菲歐〉，讀者不知道這本書是誰的故事。
3. 第 4 章寫「海倫沒有忘記和雷昂的約定」，但前文從未出現雷昂與約定；第 2 章裡海倫「想起自己說『我一定回來』時，柯爾特默默點頭」——這句承諾在模擬中根本沒發生過。整段劇情只出現一位配角（柯爾特）。

**根因（對照 `src/09_story.js`、`09t_*.js`）**
- **R-a 場景模板不認職業**：`g_train` 等模板寫死「木劍／素振り」，沒有 `jobs` 限制；魔法師、藥師、農夫都會被分到。
- **R-b 配角是隨機抽的**：`castOf()` 在事件演員不足 2 人時，用 `rg.int` 從存活居民隨機補人（只有「冒險者場景」才限定冒險者）。所以第二人與主角在模擬裡可能毫無關係。
- **R-c 承諾回收對不到人**：記憶 `memOf().promise.who` 在 `party_formed/boss_expedition` 時設成「隊伍裡的下一個人」（雷昂），但同時場景模板本身自己捏造了一個承諾對象（柯爾特）。兩套來源不一致，且前文從未寫出「和雷昂約定」那一幕。
- **R-d 模板會陳述模擬沒有的事實**：「我一定回來」「想起自己說過…」「第一次看到的魔狼」（`ch.M` 為隨機怪物，不是該事件的怪物）違反 §0 規則 4（事實由模擬鎖定）。
- **R-e 弧線沒有「這章為什麼是這個人」**：弧線上限內輪流給不同人立傳，章與章之間沒有交代轉場，讀起來像不同書混排。

**修法（依序做；每項附測試）**

**F0 讀者可懂原則（最高原則，凡與下列 F1～F6 衝突，以本條為準）**
> 故事的內容必須讓**讀者**看得懂，而不是只有系統看得懂。系統內部記得的事（記憶旗標、關係數值、隱藏事件）若沒有在書頁上出現過，對讀者就等於不存在，**不得拿來當前提**。
- **先出現、才能被引用**：任何人物、約定、傷痕、遺物、地點，在被「回想／延續／提及」之前，必須已在**讀者看過的章節**裡出現過（或在本章內先交代）。系統裡有、書裡沒寫的，一律視為沒有。
- **首次登場要交代**：人物第一次出現在書頁時，附職業與和主角的關係（如：「柯爾特，同隊的劍士」）；其後可只用名字。
- **回收要能指到出處**：回想句必須能對應到書中某一章（內部記錄 `refChapterId`）；找不到出處就改寫成當場可理解的說法，或刪除該句。
- **一章自成理解**：只讀這一章＋它的「前情」兩句，就能知道：誰、在哪、想要什麼、發生了什麼、和誰有關。需要前文才懂的地方，「前情」必須補上。
- **不寫讀者無法判斷的暗示**：例如沒有鋪陳的「那個約定」「老樣子」「當年的事」。
- **驗收（新增 `test/reader_check.js`，30 seeds × 日/中）**：逐章模擬「只看已讀內容的讀者」——
  1. 章中出現的每個人物名，都已在更早的章節或本章內交代過身分 = 100%；
  2. 每個回想/約定/傷痕/遺物，都找得到出處章節 = 100%；
  3. 每章含「誰／何處／想要什麼／發生什麼」四要素 ≥ 95%；
  4. 抽樣 10 章給人（SEVEN）盲讀：「看不懂的地方」＜ 1 處/章。


**F1 事實綁定（最重要）**——模板只能引用「事實卡」裡有的東西。
- 每章先由事件建立 `facts`：`{ povId, otherIds[], place, monsterId(實際事件怪物), relation(A→B 實際關係：師徒/隊友/家人/戀人/仇敵/無), prevChapterIds[], promiseEventId? }`。
- 模板每一句標 `needs`（例：`needs:['relation:mentor']`、`needs:['promise']`、`needs:['monster']`、`needs:['job:fighter']`）；`needs` 不滿足的句子不得被選。
- **沒有「承諾事件」就不得出現承諾句**。要有承諾句，必須先由模擬產生 `promise_made` 事件（在 depart/出征前夜類場景落實），並成為前一章的內容；回收時引用同一 `promiseEventId`，名字取自該事件，不得另抽。
- 怪物名、地點、時間詞一律取自事件本身；缺資料就用不指名說法（「一隻魔物」），不得隨機抽。

**F2 職業與場景相容表**
- 每個場景/每句模板加 `jobs`（`fighter|mage|healer|civil|any`）：
  - 木劍/揮劍/劍術 → 劍士、騎士（劍士系）；
  - 咒文/魔力/魔導書/法杖 → 魔法師；
  - 祈禱/治療/藥草 → 僧侶、藥師；
  - 農具/收穫 → 農夫；等。
- 沒有對應職業變體時，改用「職業中立」句（例：「練習」「反覆練了很多次」）；**嚴禁**把魔法師寫成練劍、把藥師寫成揮劍。
- 驗收：全文 grep 檢查「POV 職業 × 專屬名詞」不一致 = 0（建立 `job_nouns` 對照表；日/中皆要）。

**F3 配角必須有實際關係**
- `castOf()` 補第二人時，優先序：事件演員 → 師徒/配偶/戀人 → 同隊 → 關係值最高者 → 同場地同日在場者。**禁止無關係的隨機補人**；找不到就改寫成單人場景（prot=1），不要硬湊兩人。
- 章頁首顯示「與誰」＋關係（例：`海倫（魔法師）與柯爾特（劍士・同隊）`）。
- 驗收：每章第二人與 POV 的關係 ≠ 無，100%。

**F4 一本書要有「主線人物」與轉場**
- 開局每世先指定 1 位**主角候選**（由玩家第一次介入對象、眷顧者或最高潛力冒險者決定）；前 N 章（建議 6–8）以其為主，插入其他人物時必須有**轉場句**（「同一天，在鎮的另一頭…」）與關聯（他/她與主角的關係，或同一事件的另一面），否則不立章、進雜記。
- 〈丹恩與菲歐〉這類與主角無關的章，只能在「雙主角線」建立後出現，且章首「前情」要說明他們與主角線的關聯。
- 每章頁首顯示「所屬線」，書庫左欄加「依故事線」（見 C5）。

**F5 前文鋪陳先於引用（回收守則）**
- 任何「回想／約定／上次／那天」類句子，只能引用**已經成章或已記錄為事件**的內容；引用時帶「在第 n 章」的內部連結。
- 新增 Continuity 規則：回收句的對象名字必須等於被引用事件的當事人。

**F6 場景一致性小項**
- 同一章內地點一致（第 2 章頁首寫「酒館」、內文「屋頂」「房間」互相矛盾時，以頁首為準）；
- 年齡/職業/所在地以事件發生當下的狀態為準。

**驗收（加入 `test/story_check.js`，30 seeds × 日/中）**
| 檢查 | 通過標準 |
| --- | --- |
| 職業不符名詞 | 0 |
| 章中出現的人物，皆在事件演員或其關係鏈內 | 100% |
| 承諾/約定/回想句有對應事件 | 100%（無對應 = 0 句） |
| 每章第二人與 POV 有實際關係 | 100% |
| 前 8 章 POV 分布：主角候選占比 | ≥ 60% |
| 非主角章含轉場句或關聯說明 | 100% |
| 手動抽讀：每 seed 前 8 章人工打分（誰的故事／有無矛盾） | 平均 ≥ 4/5（SEVEN 或 Claude 評） |

**開發順序建議**：F0 是原則與驗收，F1＋F2（先止血，改模板標註與選句）→ F3 → F5 → F4 → F6。F1 做完前，**不要再新增模板數量**（目前 41 組場景只是量，邏輯錯會被放大）。

## B. 試玩新發現的問題（M0 其餘項目）

1. **教學視窗被切到畫面外／蓋住操作**：第 4 步（施放）與第 7 步（書庫）視窗貼在畫面下緣，「跳過／下一頁／關閉」按鈕被切掉一半，並蓋住神力列與書庫的「關閉」。→ 視窗須依聚光燈位置自動避讓（優先放在遠離目標、且完整落在 viewport 內），任何尺寸（1280×720、1366×768、行動橫向）都不得截斷。
2. **教學選到非建議神力會卡住**：第 3 步按 `1`（神諭）會跳出方向選單，教學停在第 4 步且被選單蓋住，玩家不知道要選方向。→ 教學中：選單出現時教學文字改為「選一個方向就好」；或教學期間只放行建議神力（其他灰掉並提示「先試建議的」）。
3. **結果橫幅蓋在史官書庫上**：開書庫時施放結果橫幅仍浮在 modal 上面，擋住章節內容。→ modal 開啟時橫幅/toast 必須排在其下或暫存到關閉後。
4. **祈禱面板在 4 張以上時被「事件」面板壓住**，第 4 張卡被切掉。→ 面板固定高度＋內部捲動，或只顯示最緊急 3 張＋「還有 n 件」。
5. **名字標籤在人群聚集時重疊/截斷**（例：「！妮娜」「！賽西爾」「！拉」疊在一起）。→ 實作 §4.1 的標籤避讓（上下錯開或引線）；「！」改成獨立小圖示，不佔名字長度。驗收：36 人、×1 與 ×64 各截一張，重疊率 < 5%。
6. **一開始全部 HUD 同時出現**（目標、祈禱、事件、眷顧者、熱鍵、天秤、神力列、顧問…）資訊過載。→ 實作 §2.4 分段解鎖（鎖定者半透明＋滑過顯示用途），教學結束/跳過才全開；設定提供「完整 UI 開始」。
7. **教學 12 步偏長，且 5 步是純「下一頁」被動頁**（祈禱卡說明、結果、天秤、速度、結尾）。→ 收斂為 §2.2 的 9 步，被動說明改成「做中學」或合併；並加入**因果回響步驟**（現教學沒有回響，見 §2.3）。
8. **史官書庫左欄「立傳（主角）」在尚無主角時是空白**；第1章「序章」主角「—」且內文空。→ 空狀態要有一句說明（「還沒有人成為主角。史官正在觀察。」）；序章要有真的序章文字（世界概況＋神的三動詞）。
9. **低風險日常被當成章**：兩年內 14 章，其中「第一次戰鬥」「早晨練習」「流汗之後」等多為日常。→ 依 §7.3 閘門，「狀態改變」或「推進故事線」至少成立一項才成章；其餘進「雜記」。一局目標 60–80 章維持，但**前 3 年不要超過 8 章**，讓玩家有「一本書慢慢長出來」的感覺。
10. **story_check 1/60 局 FAIL（重複率）**：修到 60/60（含日/中），並把失敗 seed 列入回歸清單。
11. **test/tut.js 依賴 Windows Chrome 路徑**：改為環境變數 `CHROME_PATH`，或支援 Playwright 內建 chromium，讓 Linux/CI 能跑。
12. **日文版同樣流程再走一遍**（教學/書庫/結局）並附截圖；本次試玩以中文為主，日文僅跑自動檢查。

## 0. 共通規則（不可違反，沿用 V3）
1. 單一 `index.html`（由 `src/*.js` 以 `node build.js` 產生）；無網路、無外部素材；程式生成圖與音。
2. 日文／繁體中文**同步**；兩語各自撰寫，不互為直譯；新增文字兩語一起交付。
3. 模擬使用 seeded RNG；新增的選文、選章、教學偏置都走同一個 seed（同 seed → 同結果）。
4. 事實由模擬鎖定：章節/場景只能引用已存在的事件、人物、關係、持有物；**不得生成模擬中不存在的事實**。
5. 不做小遊戲；成否判定維持 4 級（大成功/成功/曲解/失敗）。
6. 不新增職業、國家、神格、神力種類。
7. 文字量限制：任何卡片主文 ≤ 2 句（日 ≤ 60 字、中 ≤ 40 字），其餘放「展開」。
8. 既有存檔格式 `rinne_tenbin_v1_slot1` 若不相容，需版本號遷移或明確提示。
9. 每個里程碑完成後跑 smoke／lang／soak／batch3 與新增測試，附日/中截圖各 6 張。

### C4（P0，本作核心賣點）因果種子與因果回響（→ M2）
> 現況：完全未實作。這是 v0.2 最大缺口，優先序最高。

#### 資料
```js
// 玩家介入產生種子
seed = { id, t, castId, targetId, kind /*grace|oracle|trial|soul|faction|silence*/,
         result /*great|ok|twisted|fail*/, tags:[], state:'dormant'|'sprouting'|'bloomed',
         linkedThreadIds:[], bloomEventIds:[] }
// 重大事件記錄成因
event.causes = [ { eventId, strength:0..1 } ]; event.playerCauseIds = [seedId...]
```
#### 規則
- 重大事件（英雄成名、死亡、轉生揭曉、章節高潮）追溯最多 3 層因果，找出 `playerCauseIds`；有結果才顯示「因果回響」。
- 回響卡：`✦ 因果正在回響｜現在：…｜←(n 年前)…｜←(m 年前)你回應了…`；自動暫停（S 級）。

## 17. 應保留（不要因修改誤刪）

神不能直接操控居民；居民有自由意志可誤解／拒絕；神力有成本與副作用；結果延遲；天秤不是越光越好；眷顧者跨世追蹤；前世因果影響下一世；英雄與魔王同源；史官有目擊／轉述／推想；事實由模擬鎖定；日/中獨立撰寫；單機買斷、成品屬玩家；不做小遊戲。

## 18. 不應走偏

不變成直接操控勇者的 RPG；顧問不給唯一解；不把所有居民塞進小說；不讓普通事件亂跳通知；不為連貫而讓程式自由創造新事實；不一次解釋所有系統；核心未成立前不堆內容；小說輸出不是結局後的附贈品。
