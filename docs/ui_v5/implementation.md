# UI v5 美術定稿與程式接入指示書

2026-11-25 · 適用《輪迴之天秤／輪廻の天秤》遊戲中介面。

本交付是美術素材與互動設計，不是已合併的遊戲功能。依 SEVEN 最新指示，v5 提案作為功能參考，美術重新設計；**取消每個小面板收合，改成上方／地圖資訊／下方三區控制，以及全部顯示、觀景模式**。這項決定取代提案「只有全開全關」及舊版獨立箭頭規則。標題、世界點陣與玩法不在這次修改範圍。

## 1. 交付入口

- `assets/design/ui_v5/`：85 張可直接載入的 PNG、`manifest.json` 與逐檔 `manifest.md`。PNG 合計 25,850 bytes，無內嵌文字，透明像素只有 alpha 0；可見像素只有 255。
- `docs/ui_v5/preview.html`：以實際遊戲地圖為底的互動外觀稿。下載專案後以瀏覽器開啟；支援繁中／日文、三區切換、觀景與恢復、分頁、評定會兩項選擇及戰報。頁面下方的預覽控制列不屬於遊戲。
- `docs/ui_v5/mockup/`：1280×720 繁中與日文各 6 張：一般 HUD、區域設定、三區關閉、觀景、評定會、戰報。
- `game_map.png` 是從專案遊戲直接擷取的背景，只用於驗收，不可當作正式地圖素材。
- `validation.json`：外觀稿瀏覽器檢查結果。`build_assets.py` 是可重建的原始美術定義，不依賴外部圖像服務。

**程式先閱讀此文件，再開啟預覽；不要把 mockup 整張貼到遊戲中，也不要把預覽的示例資料接進正式遊戲。**

## 2. 視覺原則

使用深藍實色底、細金框與少量角飾。只有選中／危急狀態增加強調，不讓所有框同時發亮。五種神力採眼、枝葉、警示三角、靈魂、天秤的不同輪廓，搭配青／綠／橙／紫／金色玻璃切面；不能只依顏色判斷。

| 用途 | 色碼 |
|---|---|
| 主底／最暗底 | `#101e35`／`#080f20` |
| 主文字／次要文字 | `#f6f2e8`／`#b6c5d4` |
| 金框／重點文字 | `#bea271`／`#f3dfaa` |
| 焦點／危急文字 | `#9ed7e4`／`#ffb19b` |

文字由 DOM／程式顯示，不減色、不使用點陣圖取代一般文字。PNG 使用 nearest-neighbor / `image-rendering: pixelated`，文字仍採正常字型渲染。繁中優先 Noto Sans TC、Microsoft JhengHei；日文優先 Noto Sans JP、Yu Gothic。標題可用同語系明朝體。未附字型檔，不另增加下載；正式版需在實際部署字型上重測長句。

| 層級 | 字級／行高 | 規則 |
|---|---|---|
| 資源主要數字 | 27／30 px | 上限另用 16 px；使用等寬數字 |
| 大視窗標題 | 28／42 px | 評定會、戰報 |
| 區塊標題 | 22／33 px | 只在單一側欄及大視窗使用 |
| 常用操作、力量名稱 | 20／28 px | 不縮小長名稱 |
| 一般內文／分頁 | 18／27 px | 分頁固定單行，長文換行或捲動 |
| 次要說明 | 16／24 px | 不能承載唯一的重要資訊 |
| 熱鍵角標 | 14 px | 純輔助，操作名仍為 20 px |

按鈕可點擊範圍至少 44×44 px。禁止用文字縮到 11–13 px 解決擠壓。焦點框採 3 px 青色 outline，offset 3 px；disabled 有可見理由，selected 同時有底線／勾選／文字狀態。

中央 **x=320,y=160,w=640,h=400** 不放常駐面板。提示泡泡、地圖、對話視窗等暫時浮層可以覆蓋，但須可取消，並避免遮住它正在說明的按鈕。

全開模式以元素外接矩形計算，約佔畫面 **40.5%**（含未實心填滿的文字提示區）。這版優先保留可讀字級，**不宣稱達成舊規格 ≤30%**。觀景常駐區約 4%，沒有側欄或底部按鈕。正常顯示仍保留中央操作區及左側地圖視野；玩家可一次關閉整個區域，不必逐框整理。

右欄只有一個捲動內容區，標題／分頁／底部提示固定；內容過多在欄內捲動，不把整個欄延長到力量列。一般 HUD 不顯示長教學；首次教學分步短句，完成即消失。沒有來襲時戰況列顯示簡短和平狀態，避免頻繁上下跳動。

1280×720 是此次已驗證尺寸。較大視窗仍以原生 UI 像素錨定四邊，不把文字跟地圖一起放大。小於 1280 寬時禁止整張縮到小字：右欄改為由「村莊消息」入口打開的覆蓋抽屜，頂列先收起次要天秤說明，數字及操作至少 16 px；小於 960×600 提示提高視窗尺寸。此響應式分支需程式實作後另行驗收，本次不是已完成的窄螢幕版本。

## 4. 三區顯示規則（最重要）

右上只有「介面顯示」與「選單」兩個入口，不在每個小框增加 x、箭頭或收合鈕。這裡禁止加入逐祈禱卡、逐力量、逐資源獨立開關。

| 開關 | 一起控制的內容 | 不受影響 |
|---|---|---|
| 上方資訊 | 信仰／天秤／時間速度／戰況摘要 | 世界繼續顯示；恢復入口保留 |
| 地圖資訊 | 右側祈禱、事件、眷顧、神旨；地圖入口；任務資訊 | 遊戲地圖本身、居民與建築 |
| 下方操作 | 五種力量、目標提示、施放說明 | 已存在的遊戲狀態；隱藏不能自動施放 |
| 全部顯示 | 三區都 true，離開觀景 | 不重設分頁、捲動位置或遊戲進度 |
| 觀景模式 | 暫存三區組合，隱藏三區 | 精簡信仰／日期速度、返回操作 U |
| 返回操作 | 恢復進入觀景前的三區組合 | 不強制變成全開 |

若只關上方，右上原位保留「介面顯示」入口；即使三區都關，也能用這個入口全開。不沿邊留下每區小箭頭。全關三區不等於觀景：前者完全依玩家勾選，後者另保留精簡列且可一次恢復之前組合。

新欄位建議 `Game.settings.uiV5 = {version:1, top:true, map:true, bottom:true}`；觀景是暫時狀態，保存 `beforeView`，不可覆寫三區偏好。只存三個布林值，讀取時白名單校驗。新版本第一次全部開啟，不以舊 `collapsed` 的七種開關猜測新組合。保留舊存檔資料但停止套用舊 CSS；不得影響世界存檔。

新通知不能自動展開隱藏區域。普通通知 3 秒消失，入口保留未讀提示；危急通知可常駐至玩家確認，但不可遮住恢復入口。避免閃爍動畫，採固定徽記與「有新消息」文字。打開顯示設定不應改變遊戲時間；大視窗暫停與否沿用 `Game.timeStopped`／modal 系統。

## 5. 操作與資訊流

- **U**：觀景／恢復，沿用既有快捷鍵。**Tab 留給鍵盤焦點巡覽**，不照提案拿來隱藏 UI。
- **Esc**：依序關最上層視窗、顯示選單、取消神力瞄準；都沒有才開遊戲選單。視窗關閉後焦點回原按鈕。
- 1–5 選力量，Space 暫停，Q/E 調速度，B 備戰，H/R/S/G/N/M 等既有功能保留，**M 已是靜音，不能改成地圖**。
- 速度沿用 `[1,4,16,64]`，不新增 ×2／×8。上方速度按鈕開清楚的選項；精簡列可顯示暫停／速度，不讓玩家猜遊戲是否仍在走。
- 隱藏下方操作時取消瞄準提示，且不接受新的 1–5 施放選擇；重新顯示後仍須明確選目標。焦點在輸入、select、dialog 時停用世界快捷鍵。
- 右欄分頁：祈禱／事件／眷顧／神旨。日文：祈り／事件／眷顧／神旨。選中分頁有金底線；未讀用點及數字，不能只變色。ArrowLeft/Right 切換分頁，Tab 進入內容。
- 五神力 id 與完整名稱使用 `POWERS`，順序 oracle/grace/trial/soul/force 不變。費用每次 refresh 呼叫 `powerCost(id)`；不能把預覽 6/11/25/30/40 寫死。
- 不足信仰顯示灰底並註明「信仰不足」，不適用目標則顯示「不適用」，兩者不能都只變灰。滑鼠與鍵盤焦點都能讀取效果與原因。hover、selected、disabled 素材皆已提供。
- 神眼、畏怖與神格詳細資料移至神域／相關資料視窗，不能刪除資訊；信仰區可開啟完整說明。少用功能集中在選單兩組：村莊與紀錄（居民、靈魂、史官、神眼、顧問、操作說明）；遊戲（儲存／讀取、設定、返回標題）。返回標題沿用原有未存檔確認。
- 地圖按鈕打開大地圖視窗，使用現有世界資料重新繪製；點地圖定位鏡頭，關閉返回原分頁與三區設定。不要拿驗收背景當地圖。
- 評定會沿用 **三選二**，選中卡有勾選與底線，選滿兩張前確認不可按；滿兩張後要先取消一張才能換選。神敕最多一項、預設無，費用在確認前顯示，不點卡就扣款。內容由 `G.council.offer`、`DECREES`、`EDICTS` 取得。
- 戰報先顯示結局，再顯示傷亡、破壞、神力介入與後續可做事項。勝利也要呈現損失；戰敗使用危急底與明確「戰敗」文字，不能仍顯示「守住了村莊」。歷史、名單、修復按鈕接既有功能，不創造玩法。

## 6. 素材接法

所有九宮格以 `manifest.json` 為準；`nine_slice` 順序 **top, right, bottom, left**。面板 16 px、卡片／一般按鈕／力量按鈕 12 px、分頁 8 px。固定角不拉伸、邊只沿單一軸延展、中心實色填滿；不把完整 48px 按鈕整張拉到 148px。

```css
.ui-v5-panel {
  border: 16px solid transparent;
  border-image: url(ui_side_panel.png) 16 fill stretch;
  image-rendering: pixelated;
}
.ui-v5-button {
  border: 12px solid transparent;
  border-image: url(ui_button_normal.png) 12 fill stretch;
  min-height: 44px;
}
```

PNG 不含標籤、費用、熱鍵或通知文字。程式把文字放在內容區；不要把「PNG 不抗鋸齒」誤套到 DOM 文字。

| 元件 | 使用檔案 |
|---|---|
| 頂列／側欄／地圖 | `ui_topbar`／`ui_side_panel`／`ui_map_window` |
| 戰況 | `ui_battle_normal`／`ui_battle_danger` |
| 分頁 | `ui_tab_normal`／`selected`／`unread` |
| 清單 | `ui_card_normal`／`hover`／`selected`／`urgent` |
| 五力量 | `power_<id>_<normal,hover,selected,disabled>`＋`icon_power_<id>_32` |
| 大視窗說明圖示 | `icon_power_<id>_64`，不把 32 版模糊放大 |
| 通用按鈕 | `ui_button_<normal,hover,pressed,selected,disabled>` |
| 顯示控制 | `ui_display_menu`、`ui_visibility_<open,closed,notification>` |
| 通知／教學 | `ui_notification`、`ui_tooltip`、`ui_tooltip_arrow` |
| 大視窗 | `ui_modal`、可選 `ui_titlebar` |
| 捲動／量表 | `ui_scroll_track`、`ui_scroll_thumb`、`ui_meter_*` |
| 焦點 | `ui_focus` 或預覽中的 CSS outline，勿兩者重疊 |

檔名表省略 `.png`；完整名稱見 manifest。框架來源相同的不同神力按鈕刻意共用形狀，辨識由神力圖示與文字負責；程式可依 hash 去重，但交付保留五組明確檔名。

## 8. 實作順序與驗收

1. 接入獨立 UI v5 圖片 namespace 與原生九宮格；先顯示主 HUD。
2. 完成三區狀態、觀景恢復、存讀與舊收合邏輯移除。
3. 接回所有動態資料、世界選擇、神力、祈禱、未讀、神旨、備戰。
4. 套用評定會、戰報、地圖、通用視窗；檢查資料極端值與長句。
5. 遊戲實機截圖與美術 mockup 並排，再交 SEVEN 看實際操作。

必驗情境：繁中／日文，首次啟動、讀舊檔、各區分別關閉及全部關閉、全開、觀景恢復原組合、通知不自動展開、關閉頂列仍可滑鼠恢復、重載保留偏好、模態 Esc／焦點返回、Tab 完整巡覽、信仰 0／滿值／費用變動、5 種力量四狀態、無祈禱／大量祈禱／長姓名、評定會 0/1/2 張、神敕不足、戰報五種結局與零／大量損失、鏡頭 ×1/×2 HUD 不變、1280×720 無溢出及窄螢幕分支。

外觀稿已檢查三區與觀景互動、兩語系標籤、中央淨空、評定會選擇數限制與瀏覽器錯誤。這不等同遊戲接入測試；上述遊戲資料、重載、音效、存檔、戰鬥流程仍由實作端驗收。禁止因美術預覽能按就標示遊戲已完成。
