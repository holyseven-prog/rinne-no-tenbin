## B. 試玩新發現的問題（先修，M0，約半天～一天）

1. **教學視窗被切到畫面外／蓋住操作**：第 4 步（施放）與第 7 步（書庫）視窗貼在畫面下緣，「跳過／下一頁／關閉」按鈕被切掉一半，並蓋住神力列與書庫的「關閉」。→ 視窗須依聚光燈位置自動避讓（優先放在遠離目標、且完整落在 viewport 內），任何尺寸（1280×720、1366×768、行動橫向）都不得截斷。
2. **教學選到非建議神力會卡住**：第 3 步按 `1`（神諭）會跳出方向選單，教學停在第 4 步且被選單蓋住，玩家不知道要選方向。→ 教學中：選單出現時教學文字改為「選一個方向就好」；或教學期間只放行建議神力（其他灰掉並提示「先試建議的」）。
3. **結果橫幅蓋在史官書庫上**：開書庫時施放結果橫幅仍浮在 modal 上面，擋住章節內容。→ modal 開啟時橫幅/toast 必須排在其下或暫存到關閉後。
4. **祈禱面板在 4 張以上時被「事件」面板壓住**，第 4 張卡被切掉。→ 面板固定高度＋內部捲動，或只顯示最緊急 3 張＋「還有 n 件」。
5. **名字標籤在人群聚集時重疊/截斷**（例：「！妮娜」「！賽西爾」「！拉」疊在一起）。→ 實作 §4.1 的標籤避讓（上下錯開或引線）；「！」改成獨立小圖示，不佔名字長度。驗收：36 人、×1 與 ×64 各截一張，重疊率 < 5%。
6. **一開始全部 HUD 同時出現**（目標、祈禱、事件、眷顧者、熱鍵、天秤、神力列、顧問…）資訊過載。→ 實作 §2.4 分段解鎖（鎖定者半透明＋滑過顯示用途），教學結束/跳過才全開；設定提供「完整 UI 開始」。
7. **教學 12 步偏長，且 5 步是純「下一頁」被動頁**（祈禱卡說明、結果、天秤、速度、結尾）。→ 收斂為 §2.2 的 9 步，被動說明改成「做中學」或合併；並加入**因果回響步驟**（現教學沒有回響，見 §2.3）。
8. **史官書庫左欄「立傳（主角）」在尚無主角時是空白**；第1章「序章」主角「—」且內文空。→ 空狀態要有一句說明（「還沒有人成為主角。史官正在觀察。」）；序章要有真的序章文字（世界概況＋神的三動詞）。
9. **低風險日常被當成章**：兩年內 14 章，其中「第一次戰鬥」「早晨練習」「流汗之後」等多為日常。→ 依 §7.3 閘門，「狀態改變」或「推進故事線」至少成立一項才成章；其餘進「雜記」。一局目標 60–80 章維持，但**前 3 年不要超過 8 章**，讓玩家有「一本書慢慢長出來」的感覺。
10. **story_check 1/60 局 FAIL（重複率）**：修到 60/60（含日/中），並把失敗 seed 列入回歸清單。
11. **test/tut.js 依賴 Windows Chrome 路徑**：改為環境變數 `CHROME_PATH`，或支援 Playwright 內建 chromium，讓 Linux/CI 能跑。
12. **日文版同樣流程再走一遍**（教學/書庫/結局）並附截圖；本次試玩以中文為主，日文僅跑自動檢查。

## 0. 共通規則（不可違反，沿用 V3）
1. 單一 `index.html`（由 `src/*.js` 以 `node build.js` 產生）；無網路、無外部素材；程式生成圖與音。
2. 日文／繁體中文**同步**；兩語各自撰寫，不互為直譯；新增文字兩語一起交付。
3. 模擬使用 seeded RNG；新增的選文、選章、教學偏置都走同一個 seed（同 seed → 同結果）。
4. 事實由模擬鎖定：章節/場景只能引用已存在的事件、人物、關係、持有物；**不得生成模擬中不存在的事實**。
5. 不做小遊戲；成否判定維持 4 級（大成功/成功/曲解/失敗）。
6. 不新增職業、國家、神格、神力種類。
7. 文字量限制：任何卡片主文 ≤ 2 句（日 ≤ 60 字、中 ≤ 40 字），其餘放「展開」。
8. 既有存檔格式 `rinne_tenbin_v1_slot1` 若不相容，需版本號遷移或明確提示。
9. 每個里程碑完成後跑 smoke／lang／soak／batch3 與新增測試，附日/中截圖各 6 張。

### C4（P0，本作核心賣點）因果種子與因果回響（→ M2）
> 現況：完全未實作。這是 v0.2 最大缺口，優先序最高。

#### 資料
```js
// 玩家介入產生種子
seed = { id, t, castId, targetId, kind /*grace|oracle|trial|soul|faction|silence*/,
         result /*great|ok|twisted|fail*/, tags:[], state:'dormant'|'sprouting'|'bloomed',
         linkedThreadIds:[], bloomEventIds:[] }
// 重大事件記錄成因
event.causes = [ { eventId, strength:0..1 } ]; event.playerCauseIds = [seedId...]
```
#### 規則
- 重大事件（英雄成名、死亡、轉生揭曉、章節高潮）追溯最多 3 層因果，找出 `playerCauseIds`；有結果才顯示「因果回響」。
- 回響卡：`✦ 因果正在回響｜現在：…｜←(n 年前)…｜←(m 年前)你回應了…`；自動暫停（S 級）。
- 種子狀態在 UI 可追蹤，但**不顯示唯一答案**（不劇透）。
- 回響不得偽造：只用模擬中真實存在的因果邊。

### C5（P0 骨架 / P1 完整）故事線引擎差額（→ M2）
現有：章節弧線、記憶、伏筆、41 組場景模板、承接引用、Continuity 檢查已存在（見 A）。**尚缺**：
- **Story Thread 資料與聚光燈名額**（§7.2）：同時活躍 3 條（主1＋次2）＋候補 3；超出者進「雜記」；玩家可「請史官追這個人」（現有「追蹤此人」須接到權重）。
- **命運舞台**：同時只把 3–8 人放到舞台中央（主角候選、活躍線人物、眷顧者、將高潮者、與玩家過往神力有關者）；UI 顯示每條線：標題／焦點人物／階段／未解問題。
- **左欄加「依故事線」**（現有依時間/依人物）。
- **伏筆物件狀態**（born/seen/reappeared/dormant/paid/legacy；同一伏筆最多提醒 3 次；年末列「未解之謎」）；回收章標 ☆。
- **Scene Card + forbiddenFacts**（§7.7）；Continuity Checker 擴到：知情、遺物持有者、誓言、前世是否揭曉、稱號一致；三次失敗降為雜記。
- **人物接力與遺產**（§7.6）：死亡後弟子/子女/遺物/誓言接力，線進入 `legacy`，UI 顯示 `✦ 命運線重新連接`。
- 左欄可切「依時間／依人物／依故事線」；人物名下顯示 第1話、第2話…；有「追蹤此人」。
- 同一 POV 連續 2–4 話後才換；5 章內不得出現相同標題。

新增驗證：B-1/3/4/5 以 Playwright 截圖（1280×720、1366×768）檢查「無截斷、無重疊」；教學 E2E 加入「選到非建議神力」「中途關閉書庫」「跳過」三條分支。

神不能直接操控居民；居民有自由意志可誤解／拒絕；神力有成本與副作用；結果延遲；天秤不是越光越好；眷顧者跨世追蹤；前世因果影響下一世；英雄與魔王同源；史官有目擊／轉述／推想；事實由模擬鎖定；日/中獨立撰寫；單機買斷、成品屬玩家；不做小遊戲。

## 18. 不應走偏

不變成直接操控勇者的 RPG；顧問不給唯一解；不把所有居民塞進小說；不讓普通事件亂跳通知；不為連貫而讓程式自由創造新事實；不一次解釋所有系統；核心未成立前不堆內容；小說輸出不是結局後的附贈品。
